## The framework comes first

The framework profile and the files in the repository are the source of truth. Reuse the team's
fixtures, clients, helpers, imports, naming and folder conventions exactly. Read the example tests
named in the profile and copy their structure. Never add npm dependencies, never change
configuration, fixtures, clients or other tests. If something you need is missing (for example a
way to call the API without credentials), build it inside the spec file with Playwright's own
`request` / `playwright.request.newContext()` and mention it in `notes`.

## File layout

- One spec file per endpoint, in the profile's test directory, named the way the team names files.
- A short header comment: `// Generated by API Test Studio for <METHOD> <path>. Keep the TC-#### ids in test titles.`
- One `test.describe('<METHOD> <path>', ...)` block (or the team's grouping style).
- One `test()` per test case. The title **starts with the case code**: `'TC-0005 Reject missing required field name'`.
  Add the team's tag style if it has one (e.g. `@smoke` for P1 positive cases, `@unit`).
- Tests are independent: each creates the data it needs and cleans up after itself.

## Translating a test case

| Case field | Code |
| --- | --- |
| `preconditions` | Arrange steps at the start of the test (create resources through the API, using the team's client). |
| `request.pathParams/query/headers/body` | The request the team's client or `request` makes. Values are literal unless they are placeholders. |
| `request.auth` | `valid`: the framework's normal authenticated client. `none`: a request context with **no** credentials. `invalid`: a context with `Authorization: Bearer invalid-token` (or an invalid API key in the team's header). `expired`: a token from `process.env.API_TOKEN_EXPIRED`. `insufficient`: a token from `process.env.API_TOKEN_LIMITED`. For the last two, use the runtime guard below. |
| `expected.status` | `expect(response.status()).toBe(<status>)` (or the team's helper). |
| `expected.responseSchema` | Assert the important documented fields and their types. Use the team's schema validator only if one exists. |
| `expected.bodyChecks` | `exists` → `toBeDefined()`; `not_exists` → `toBeUndefined()`; `equals` → `toEqual`; `contains` → `toContain`; `type` → `typeof` / `Array.isArray`; `matches_request` → compare with the sent value; `matches_pattern` → `toMatch(/.../)`; `one_of` → `expect([...]).toContain(value)`; `length` → `toHaveLength`; `greater_than` / `less_than` → `toBeGreaterThan` / `toBeLessThan`. |
| `cleanup` | Remove created data in `finally` blocks or the team's cleanup mechanism, so it runs when assertions fail. |

**Runtime guard for optional credentials:** for `expired`/`insufficient`, start the test with
`test.skip(!process.env.API_TOKEN_LIMITED, 'Set API_TOKEN_LIMITED to run this case');` and list the
variable in `envVariables`.

## Placeholders from test cases

| Placeholder | TypeScript |
| --- | --- |
| `{{env.NAME}}` | `process.env.NAME` (list NAME in `envVariables`) |
| `{{unique.name}}` | `` `qa-${Date.now()}-${Math.random().toString(36).slice(2, 8)}` `` (or the team's helper) |
| `{{repeat:x:51}}` | `'x'.repeat(51)` |
| `{{uuid.random}}` | `crypto.randomUUID()` (global in Node 19+) |
| `{{created.<field>}}` | The value read from the response that created the resource in the preconditions |

## Flow tests (`kind: "flow"`)

A flow case has ordered `steps`; each step has its own `request`, `expected` and `captures`.

- One spec file per flow, one `test()` whose title starts with the flow's case code, and one
  `await test.step('S1 <purpose>', async () => { ... })` per step, in order.
- Captures become typed local variables declared before the steps (`let petId = '';`) and assigned
  inside the step from the response body at the capture path. `{{steps.S1.petId}}` in a later
  request is that variable.
- Assert each step's status and body checks inside its `test.step`, so the report shows which step
  failed.
- Track every resource the flow creates and delete it in a `finally` block after all steps, so
  cleanup runs even when a step fails. Skip cleanup of resources a step already deleted.
- `endpoint.operations` contains the contracts of every operation the flow calls.

## Hard rules

- No `test.only`, no `waitForTimeout` or other fixed sleeps, no `eval`/`new Function`, no file-system
  or process access (`fs`, `child_process`, `process.exit`), no network calls other than to the API
  under test through the framework's base URL.
- No secrets or tokens in code; credentials come from the framework or environment variables.
- Strict TypeScript: type response bodies with small interfaces or `unknown` + narrowing; avoid `any`
  unless the team's tests use it.
- Keep every case: the file must contain a test for every case code you are given.
